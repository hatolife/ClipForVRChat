# v0.1.8 avatar_osc basis 実機確認手順

## 仕様前提

`avatar_osc` basis は、専用アバターギミックから VRChat OSC Avatar Parameters を受信して使う。
標準OSCだけでは動かない。デフォルトのpositionとyawはHead基準であり、player root そのものではない。

## 専用アバターの準備

- VRChatで、専用ギミックを入れたアバターを使う。
- まずは通常利用向けの `AvatarBeacon_main.prefab` を入れたアバターで、`avatar_beacon/coord/*` と `avatar_beacon/forward/*` を確認する。
- 高精度確認が必要なら `AvatarBeacon_12.prefab` を使う。必要なら `ATG/*` 互換も切り替えて試す。
- 受信対象の prefix は、実装側の status 表示と一致させる。

## 実機確認手順

1. VRChat側でOSCを有効にする。
2. 専用アバターを装着し、自動撮影タブを開く。
3. `player_local` の basis source が `avatar_osc` になっていることを確認する。
4. `AvatarBeacon受信状態` に受信中表示が出ることを確認する。
5. 最終受信時刻が更新されることを確認する。
6. position がHead位置に追従し、yaw がHead/顔の向きに追従することを確認する。
7. 一時的に別アバターへ切り替え、未受信または鮮度切れで止まることを確認する。
8. `manual` basis に戻しても、既存の手動基準位置の挙動が壊れていないことを確認する。

## OSCが送信されない場合の切り分け

VRChat公式OSC Avatar Parametersは、Published Avatarではavatar IDごとのOSC config JSONを使い、`output.address` があるparameterを値変化時に送信する。
configが古い、未生成、またはAvatarBeacon導入前の内容のままだと、新しいparameterは送信されない。

1. VRChatのAction Menuで `Options > OSC > Enabled` がONであることを確認する。
2. `Options > OSC > Reset OSC Config` を実行し、アバターを再読み込みする。
3. 必要なら `%USERPROFILE%\\AppData\\LocalLow\\VRChat\\VRChat\\OSC\\<userId>\\Avatars\\<avatarId>.json` を確認し、`avatar_beacon/coord/*` と `avatar_beacon/forward/*` の `output.address` があることを確認する。
4. ClipForVRChatのログに10秒ごとのAvatar OSC summaryが出るかを見る。
   - summaryが出ない: VRChatから `/avatar/parameters/...` が届いていない。OSC有効化、送信ポート9001、OSC config、Avatar Interactions/Contact設定を確認する。
   - summaryは出るが `missing/partial`: OSC自体は届いているが、AvatarBeacon既定parameterが届いていない。config内のaddress名、Prefabのparameter名、ClipForVRChat側prefixを確認する。
   - `stale`: AvatarBeacon既定parameterは過去に揃ったが、現在は `avatar_beacon/coord/*` と `avatar_beacon/forward/*` が鮮度切れ。summaryのlastが `Ahoge_Angle` などAvatarBeacon以外なら、VRChat OSC経路自体は動いているが、AvatarBeaconの座標parameter更新が止まっている。
5. VRChatのOSC Debug画面、またはProtokolなどのOSC受信ツールで `/avatar/parameters/avatar_beacon/coord/x` などが見えるか確認する。
6. Avatar Dynamics Contactが無効だと値が変わらない可能性があるため、VRChat側のAvatar Interactions/Contact関連設定を確認する。

### `stale` の確認

`stale / prefix: avatar_beacon` の場合、ClipForVRChatはOSC packetを受信できていても、AvatarBeaconのbasis parameterが鮮度切れになっている。
この状態では、受信ポートやファイアウォールよりも、AvatarBeacon側のOSC config、アバター再読み込み、Contact動作を優先して確認する。

1. `Options > OSC > Reset OSC Config` を実行する。
2. AvatarBeacon導入済みアバターを一度別アバターへ切り替えてから戻す。
3. `%USERPROFILE%\\AppData\\LocalLow\\VRChat\\VRChat\\OSC\\<userId>\\Avatars\\<avatarId>.json` に `avatar_beacon/coord/*` と `avatar_beacon/forward/*` の `output.address` があるか確認する。
4. Avatar Dynamics Contact / Avatar Interactions が有効か確認する。
5. VRChat OSC DebugまたはProtokolで `/avatar/parameters/avatar_beacon/coord/x` と `/avatar/parameters/avatar_beacon/forward/x` が継続更新されるか確認する。

## 撮影確認項目

- 正面、背後、斜めの `player_local` 構図で、移動後も相対構図が大きく崩れない。
- `AvatarBeacon受信状態` の最終受信時刻、position/yaw、エラー表示が UI から読める。
- 標準OSCだけの状態では、`avatar_osc` basis が使えないことが分かる。
- 受信停止時に、古い basis を使って撮影しない。
- Stream 方式と Photo 方式の両方で、basis の扱いが同じである。

## 失敗時に提出するもの

- `config.json`
- `logs/YYYY-MM-DD.log`
- 撮影画像と同名の `.json`
- 受信状態が分かる画面キャプチャ
- 使った prefix と parameter 配線のメモ
- avatar IDごとのOSC config JSON
