## 調査結果

- findingは、外部JSON設定から読み込まれた `autoPhoto.photoDirectory` / `screenshotAutoPost.screenshotDirectory` が、設定画面では通常確認できないまま保存され、自動処理watcherに使われる点を指摘している。
- 攻撃シナリオは、第三者が渡した設定JSONに `output.uploadDiscord=true`、攻撃者管理のDiscord Webhook URL、自動処理ON、広い監視フォルダを入れておき、利用者がその設定を開いて保存する流れである。
- 保存後、指定フォルダに新しく作られた対応画像は、縮小処理後に設定されたWebhookへ自動投稿される。
- 現在HEADでも `src/internal/appcore/config.go` のJSON-backed fieldとして監視ディレクトリとスキャン間隔は残っており、Normalizeは空欄時の既定値補完とtrimが中心で、外部設定由来の広い任意ディレクトリを拒否しない。
- 現在HEADの設定画面では自動写真処理とスクリーンショット自動処理のON/OFF、Webhook URLは表示されるが、通常の設定カテゴリには監視フォルダ入力が表示されていない。
- 現在HEADには自動投稿の確認ダイアログがあるが、これは送信先Webhookが未設定の場合だけ表示される。攻撃者がWebhook URLも設定したJSONでは確認が出ないため、レポートの主要シナリオは残っている。
- `saveConfigLocked` は保存後に `restartAutoPhotoWatcher` を呼び、watcherは設定由来の監視ディレクトリとWebhookを使って画像処理・Discord投稿を行う。
- 修正方針は、外部設定を保存する前に監視ディレクトリとWebhookの組み合わせを明示確認させること、隠れた監視ディレクトリを通常UIまたは専用確認画面で必ず表示・変更できるようにすること、インポート直後の自動処理ONやWebhookを安全側に無効化すること、危険な広すぎるディレクトリを拒否または強い確認対象にすることである。
