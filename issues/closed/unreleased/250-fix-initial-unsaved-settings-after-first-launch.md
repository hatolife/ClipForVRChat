# 250: 初回起動直後に未保存変更が表示される

## 指示

b8でconfig無しの状態で初回起動した直後に
未保存変更
自動撮影 OSC
がでる
'/mnt/c/Users/user/Downloads/ClipForVRChat-v0.1.8-b8-windows-amd64/logs/2026-07-07.log'
これ何なのか 何が差分扱いされているのかわからない

## 文脈

v0.1.8-b8 で未保存変更の分類表示とラベルハイライトを追加したが、config.json が存在しない初回起動直後にも「自動撮影 OSC」が未保存変更として表示されている。ログでは初期状態取得直後に `settings draft saved` が記録されており、ユーザー操作前に設定差分扱いになっている。

## 解釈

初回起動時の既定設定を UI 側へ取り込んだだけでは未保存変更扱いにしない。実際に差分が発生する場合は、どの項目が差分なのか UI とログまたは診断しやすい形で分かるようにする。

## 問題

- config なしの初回起動直後に未保存変更として「自動撮影 OSC」が表示される。
- 表示だけでは、どの具体的な設定値が保存済みベースラインとの差分扱いなのか分からない。

## 期待する挙動

- config なしの初回起動直後は、ユーザー操作前に未保存変更を表示しない。
- 未保存変更が出る場合は、具体的な差分パスを確認できる。

## 受け入れ条件

- 初回起動相当の既定設定で未保存変更が発生しない。
- 未保存変更ドラフト保存時に差分パスを診断ログへ出す。
- 関連するフロントエンド検査とテストが通る。

## 原因

- `config.json` が存在しない場合の既定設定が `Normalize()` されておらず、`autoCapture.osc.forward.targets` が `nil` のままだった。
- 一時ドラフト保存時は `Normalize()` により `targets` が空配列 `[]` になり、フロントエンドのJSON比較で `null` と `[]` が差分扱いになっていた。
- その差分パスが大分類の「自動撮影 OSC」にまとめられており、OSCタブ内の「転送先」行にもハイライトが付いていなかった。

## 対応

- configなしで `LoadConfig()` が返す既定設定も `Normalize()` するようにした。
- 一時ドラフトへ保存元configパスとベースラインを持たせ、初回起動時の旧形式ドラフトや差分のないドラフトを復元しないようにした。
- 一時ドラフト保存/復元時に具体的な差分パスを診断ログへ出すようにした。
- `autoCapture.osc.forward.targets` の表示名を「OSC転送先」にし、OSCタブ内の「転送先」行と転送先カードをハイライトするようにした。
