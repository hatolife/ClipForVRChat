# 設定保存時に変更後の設定値を診断ログへ出力する

## 問題

Discord Webhook URLが無効になっていた場合、処理時には `status=401` として分かるが、いつどの設定値で保存された状態なのかを後からログで追いにくい。

`2026-07-05T17:21:10+09:00 startup config` のような起動時設定ログはあるが、設定画面で保存した直後の変更後設定値が同じ粒度で残らないため、Webhook URLの貼り直しや自動投稿用Webhook URLのフォールバック状態を確認しづらい。

## 期待する挙動

- 設定画面で保存したとき、保存後の設定値を診断ログへ出力する。
- 出力形式は既存の `startup config` と同じ雰囲気に揃える。
- Webhook URLなどの秘密情報は、既存ログ方針に合わせて安全にマスクする。
- Discord通常投稿用Webhook URL、自動投稿用Webhook URL、VRChat写真用Webhook URL、スクリーンショット用Webhook URL、自動撮影用Webhook URLの設定有無とフォールバック結果を後から追える。

## 受け入れ条件

- [x] 設定保存成功時に `settings saved config` のような診断ログが出る。
- [x] ログには保存後の設定値が出力される。
- [x] Webhook URLやtoken相当の値は全文を出さず、既存のマスク表現に揃える。
- [x] 自動投稿系Webhookが空欄の場合、通常投稿用Webhook URLへフォールバックされる状態かどうかをログで判断できる。
- [x] 設定保存失敗時は失敗理由が診断ログに出る。

## 完了メモ

- 設定保存成功時に `settings saved config=...` を診断ログへ出力するようにした。
- 設定保存失敗時に `settings save error: err=...` を診断ログへ出力するようにした。
- 通常投稿用Webhook、自動処理系Webhook、自動撮影Webhookについて、設定有無と通常投稿用Webhookへのフォールバック状態を秘密情報なしで追えるようにした。
