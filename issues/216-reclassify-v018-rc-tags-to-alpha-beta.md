# v0.1.8既存RCタグをalpha/beta扱いへ整理する

## 問題

旧 `v0.1.8-rc1` から旧 `v0.1.8-rc44` までが、実態として release candidate ではなく機能開発・機能チェック段階の配布版として使われている。新しいバージョニング規則では、`rc` は正式リリース直前の候補だけに限定したいため、既存タグと記録を実態に合わせて整理する必要がある。

## 期待する挙動

- 旧 `v0.1.8-rc1` から旧 `v0.1.8-rc43` を `v0.1.8-a1` から `v0.1.8-a43` として扱う。
- 旧 `v0.1.8-rc44` を `v0.1.8-b1` として扱う。
- Markdown上の対応バージョン、Release URL、成果物名、分類フォルダを新しい表記へ揃える。
- 過去の調査本文で当時の呼称を残す必要がある箇所は、旧RC表記と新表記の対応が分かるようにする。
- Gitタグを新表記へ作り直し、旧RCタグを削除できる状態にする。

## 受け入れ条件

- 旧 `v0.1.8-rc1` から旧 `v0.1.8-rc43` の記録が `v0.1.8-a1` から `v0.1.8-a43` に整理されている。
- 旧 `v0.1.8-rc44` の記録が `v0.1.8-b1` に整理されている。
- `issues/closed/v0.1.8-a*` などの分類フォルダとリンクが新表記へ整理されている。
- 新旧タグの対応表または作業メモが残っている。
- タグ操作前後の確認手順が記録されている。

## 新旧タグ対応

- 旧 `v0.1.8-rc1..rc43` は `v0.1.8-a1..a43` へ移す。
- 旧 `v0.1.8-rc44` は `v0.1.8-b1` へ移す。

## タグ操作メモ

- `v0.1.8-a1..a43` と `v0.1.8-b1` を旧タグと同じcommitへ作成する。
- 2026-07-07: ローカルでは `v0.1.8-a1..a43` と `v0.1.8-b1` を旧タグと同じcommitへ作成し、commit対応が一致することを確認した。リモートへは未push。
- `v*` タグpushはRelease workflowを起動するため、新タグを一括pushすると最大44本のRelease workflowが走る。さらに、新タグが指す旧commit上のRelease workflowは `a/b` タグを受け付けない可能性が高いため、通常pushでは失敗する見込み。
- リモートタグを整理する場合は、Release workflowを一時停止してタグ参照だけ移すか、失敗するRelease workflowを許容してpushするかを決めてから実施する。
- 新タグのcommit対応を確認してから、旧 `v0.1.8-rc1..rc44` のremote/localタグを削除する。
- 既存GitHub Releaseが残っている場合は、タグ削除とは別にRelease削除または再作成を確認する。
