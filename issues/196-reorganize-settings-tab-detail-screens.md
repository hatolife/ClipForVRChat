# 設定画面タブ内の項目を概要行と詳細設定画面へ整理する

## 問題

設定画面、特に自動撮影タブが縦に長くなりすぎている。

現在は「自動撮影スケジュール」のようなON/OFF項目の直下に、依存する詳細項目が常に並ぶ。
例えばスケジュールがOFFでも、撮影間隔、初回待機時間、開始時に撮影などが同じ画面上に表示され、設定全体の見通しが悪い。

同様に「撮影後にCamera状態を戻す」以下の復元関連項目も量が多く、自動撮影タブの主要操作を探しにくくしている。

## 期待する挙動

設定画面のタブ内では、主要項目を概要行として表示し、依存する詳細項目は「詳細設定」画面へ遷移して編集できる。

例:

```text
自動撮影スケジュール
一定間隔でVRChatカメラ撮影を実行します。
OFF
[▶ 詳細設定]
```

OFF時は詳細設定ボタンをグレーアウトする。

ON時に詳細設定ボタンを押すと、その項目に依存した設定値だけを編集する詳細設定画面へ遷移する。

例:

```text
自動撮影スケジュール

撮影間隔
1回の撮影開始から次の撮影開始までの秒数です。最小10秒です。
300

初回待機時間
自動撮影開始後、最初の撮影まで待つ秒数です。
0

開始時に撮影
自動撮影を開始した直後に1回撮影します。
ON/OFF
```

## 受け入れ条件

- [x] 自動撮影タブの主要項目を棚卸しし、常時表示する概要項目と詳細設定画面へ移す項目を決める。
- [x] 「自動撮影スケジュール」は概要行にON/OFFと詳細設定ボタンだけを残す。
- [x] スケジュールOFF時は詳細設定ボタンをグレーアウトし、押せない理由が分かる。
- [x] スケジュールON時は詳細設定ボタンからスケジュール詳細画面へ遷移できる。
- [x] スケジュール詳細画面で `撮影間隔`、`初回待機時間`、`開始時に撮影`、必要なら重複実行制御や最大実行回数を編集できる。
- [x] 「撮影後にCamera状態を戻す」は概要行にON/OFFと詳細設定ボタンだけを残す。
- [x] Camera状態復元の詳細項目は復元設定の詳細画面へ移す。
- [x] 「構図プリセット」を「構図設定」に改名し、構図一覧とPose編集を詳細設定画面へ移す。
- [x] 自動撮影タブの通常表示では「構図設定」の概要行と詳細設定ボタンだけを表示する。
- [x] Spout helper、Spout sender、Stream取得、録画デバッグ、出力先、保存形式、ファイル名テンプレートを撮影/出力詳細へ移す。
- [x] サイドカーJSON、画像メタデータ、同席ユーザー情報、Discord投稿、撮影後復元を保存・投稿・復元詳細へ移す。
- [x] 詳細画面から元のタブへ戻れる。
- [x] 詳細画面で変更した値が既存の保存/キャンセル/未保存警告の挙動と矛盾しない。
- [x] キーボード操作、スクリーンリーダー、無効状態の説明に必要な `title` / `aria-label` を付ける。
- [x] mobile/狭幅表示で本文やボタンが重ならない。
- [x] Vue template変更後に `node scripts/check-frontend-template-literals.mjs` と `node scripts/check-wails-api-surface.mjs` を実行する。

## 対応メモ（2026-07-04）

- 自動撮影タブに `autoCaptureDetailView` を追加し、タブ内の詳細画面として `自動撮影スケジュール` と `撮影後にCamera状態を戻す` を切り替えるようにした。
- 通常表示ではスケジュールと復元を概要行にし、ON/OFFと詳細設定ボタンだけを残した。
- OFF時の詳細設定ボタンは無効化し、`title` と `aria-label` で理由と対象を示すようにした。
- 詳細画面の戻る操作は設定保存とは独立した画面内遷移にし、既存の未保存差分検出は設定JSON差分のまま維持した。
- 狭幅表示では概要操作と詳細ヘッダーが折り返すCSSを追加した。

## 追加対応メモ（2026-07-07）

- 自動撮影タブの「構図プリセット」は常時表示すると縦に長くなるため、「構図設定」として概要行に畳む。
- 詳細設定画面では、既存の構図一覧、構図名、座標系、Pose、拡大率、並び替え、現在Pose保存、テスト撮影などを編集できるようにする。
- 構図設定はON/OFF依存項目ではないため、詳細設定ボタンは常に押せるようにする。
- 通常表示には主要行だけを残し、Stream/Spout/出力/メタデータ/Discord/復元の詳細値は詳細画面へ分離する。

## 実装メモ

- まず自動撮影タブから始める。
- 詳細画面は既存の設定画面内状態として実装し、別ウィンドウやモーダルにしない案を優先する。
- 「ON/OFFで詳細ボタンをグレーアウト」は、詳細設定値を消す意味ではなく、編集導線だけを抑制する。
- 既存設定値はOFF中も保持し、再度ONにしたときに復元されるべき。
- 将来的に他タブにも同じパターンを適用できるよう、見出し、概要、ON/OFF、詳細ボタン、戻る導線のUIパターンを揃える。

## 検証観点

- 自動撮影タブの初期表示が現在より短く、主要項目を見つけやすい。
- スケジュールOFF時に詳細設定へ入れない。
- スケジュールON時に詳細設定へ入り、値を変更して保存できる。
- Camera状態復元OFF時に詳細設定へ入れない。
- Camera状態復元ON時に詳細設定へ入り、値を変更して保存できる。
- 保存せず戻る/閉じる場合の未保存警告が従来通り動作する。

## 調査メモ（2026-07-04）

- `src/frontend/src/main.js:1904-2209` の自動撮影タブは、構図プリセット、スケジュール、撮影方式、Spout helper、出力、メタデータ、Discord投稿、復元設定まで1画面に並んでいる。
- 概要行に残す候補は `自動撮影スケジュール`、`撮影方式`、`自動撮影保存先`、`Discord自動投稿`、`撮影後にCamera状態を戻す` あたりで、他は詳細画面へ分離するのが自然。
- `スケジュール` の詳細に移す候補は `撮影間隔`、`初回待機時間`、`開始時に撮影`。
- `撮影方式=Stream` の詳細に移す候補は `Spout helper`、`Spout sender自動選択`、`Spout sender名`、`Stream取得タイムアウト`、`Stream起動後待機`。
- `出力/メタデータ` の詳細に移す候補は `Stream保存形式`、`ファイル名テンプレート`、`サイドカーJSON`、`画像埋め込みメタデータ`、`サイドカーJSONにユーザーIDを含める`、`Discordに表示名を含める`、`DiscordにユーザーIDを含める`、`Discordに画像を添付する`。
- `復元` の詳細に移す候補は `撮影前の受信値を優先`、`受信値の有効秒数`、`戻し先 Camera Mode`、`戻し先 Streaming`、`戻し先 SmoothMovement`、`戻し先 Lock`、`戻し先 Poseを使う`、`戻し先 位置/回転`、`戻し先 拡大率/露出/焦点距離/絞り`、`戻し先 Show UI`、`戻し先 Local Player`、`戻し先 Remote Player`、`戻し先 Environment`、`戻し先 Green Screen`。
- `OSC` タブへ移していない設定は、今のところ `OSCホスト`、`OSC送信ポート`、`OSC受信ポート`、`現在Pose保存の有効秒数`、`カメラOSCリセット`、`プレイヤー基準の取得元`、`AvatarBeacon受信状態`、`OSC転送` と `OSCログ`。
- 既存の未保存警告は `settingsBaseline` と `hasUnsavedSettings` で設定全体のJSON差分を見ているため、詳細画面を別状態として持つだけなら壊れにくいが、画面遷移時に `settingsTab` を変えるだけではベースラインは変わらない。
- ただし `openSettings()` が `settingsTab = 'feature'` を前提にしているので、詳細画面から設定を開き直す導線や `leaveSettings()` の戻り先には注意がいる。
- 自動撮影タブ内の `syncSettingsTabRuntime()` は `settingsTab === 'osc'` のときだけ `avatar_osc` polling と OSCログ購読を開始するので、詳細画面を `osc` タブ外で実装するなら polling 条件を壊さない設計が必要。
- `saveSettings()` と `confirmSaveAndLeaveSettings()` は `processOnSave` と `shouldConfirmAutoPostSettings` の分岐を持つため、詳細画面から戻る/保存するボタンは既存の保存系メソッドを共有するのが安全。
